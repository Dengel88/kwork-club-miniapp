# Личный кабинет клуба — Telegram Mini App + MAX

MVP под заказ Kwork [#3268232](https://kwork.ru/projects/3268232/view):
личный кабинет клиента салона/клуба, один фронтенд для Telegram и MAX,
вход без пароля по номеру телефона.

## Что уже работает

| № | Экран по ТЗ | Статус |
|---|---|---|
| 1 | Статус клуба, прогресс до следующего, скидка, имя, телефон | ✅ |
| 2 | Бонусные карты (несколько, с балансом) | ✅ |
| 3 | «Записаться», «Онлайн-запись», «Отдел заботы» (чат с готовым текстом) | ✅ |
| 4 | Активные записи: дата/время, категория, филиал, мастер | ✅ |
| 5 | Абонементы: цена/со скидкой, оплачено/к оплате, прогресс, состав, «Заморожен» | ✅ |
| 6 | Последние визиты по 5 с пагинацией | ✅ |
| 7 | Оценка 1–5★, при 5★ — ссылка на отзыв на картах филиала | ✅ |
| 8 | Реферальная программа: текст + счётчики | ✅ |

- Тема берётся из мессенджера (светлая/тёмная, акцентный цвет).
- Без `VITE_API_URL` работает на демо-данных (`web/src/api/mock.ts`), подходит любой номер.

## Запуск

```bash
cd web
npm install
npm run dev        # http://localhost:5173
npm run build      # статика в web/dist
```

Подключение реального API: `web/.env` → `VITE_API_URL=https://api.example.ru`.
Ответ `POST /api/client/profile` маппится в `mapProfile()` в `web/src/api/client.ts`,
модель — `web/src/api/types.ts`.

## Структура

```
web/src/
  api/types.ts     модель профиля (контракт API)
  api/client.ts    запросы + маппинг ответа, демо-режим
  api/mock.ts      демо-данные
  platform.ts      адаптер Telegram / MAX / браузер (вход по номеру, чаты, ссылки, тема, haptics)
  sections.tsx     8 блоков кабинета
  App.tsx          вход и раскладка
```

## Безопасность входа

В проде ручной ввод номера скрыт: номер приходит из мессенджера через
`requestContact`, а запрос к API несёт подписанный `initData` (заголовок `X-Init-Data`).
Бэкенд обязан проверить подпись — иначе любой сможет открыть чужой кабинет, подставив номер.
